A **Process** is the core building block in Process Focus. In its
basic form it's two or more steps, done one after another. Often these
steps are done by different people in your organisation.

We call it a business process, as in a business or organisation
context we often deal with timelines: ideally we do this within so
many days. A complaints process for example would said response times
within 5 business days for example.

## What is a Process?

A process defines:

- A sequence of **steps** that need to be executed
- **Transitions** between steps (linear or conditional)
- **Data** that flows through the process
- **Participants** who interact with the process

## Process flow: steps between processes

When building a business process, you connect one step to
another. Steps can be connected sequentially, or conditionally.

A basic order process would be to enter the order, a human step, then
in the second step store the order in the order table. Those would be
unconditional steps. The third step could be conditional: pick the
order if the item is in stock, or if it is not in stock, start a
back order process.

## Process Instances

When a process is started, a **process instance** is created. Each instance:

- Has a unique identifier
- Maintains its own state and data
- Tracks which step it's currently on
- Records an audit trail of all actions

Each instance has its own execution flow.

## How work progresses

Starting a process creates an execution. As it progresses, the runtime evaluates
the process's conditions, dependencies, and schedules to determine what work
can proceed. Human work appears as To-Dos; automated steps run through the
runtime. An execution can have more than one piece of work in progress.

The path taken depends on the execution's data and the process definition.
The [workflow diagram](/docs/frontend/visualisation/) shows the authored paths,
not necessarily every step taken by a particular execution.

## Process Lifecycle

1. **Created** - Process instance is initialized
2. **Running** - Process is actively executing steps
3. **Waiting** - Process is waiting for user input or external event
4. **Completed** - All steps have been executed successfully
5. **Cancelled** - Process was terminated before completion

## Best Practices

- Keep processes focused on a single business objective
- Use meaningful names for processes and steps
- Document the purpose of each process
- Version your process definitions
